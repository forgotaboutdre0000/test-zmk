## Модуль `ves`: автоматический поиск веса опор

Этот модуль отвечает за полный цикл работы с весами опор:

- чтение входного файла с позициями;
- поиск и кэширование весов по доверенным сайтам;
- агрегация результатов по доменам;
- подготовка данных для листа Google Sheets `PDF_ZMK_VES`.

Модуль изолирован от остального кода: скрипт `write_pdf_zmk.py` использует только его публичное API.

### Файлы модуля

- `ves/test_positions.txt`  
  Тестовый список позиций (по одной на строку), на которых отлаживается пайплайн поиска веса и заполнения листа `PDF_ZMK_VES`.  
  Порядок строк в этом файле соответствует порядку строк в листе.

- `ves/weights_db.json`  
  Единая локальная база найденных весов. Хранится в виде JSON-объекта вида:

  ```json
  {
    "57-КХ-А11": {
      "name": "57-КХ-А11",
      "sources": [
        {
          "domain": "detalneftehim.ru",
          "url": "https://detalneftehim.ru/...",
          "weight": 1.4,
          "unit": "kg",
          "fetched_at": "2026-03-11T12:00:00Z"
        }
      ],
      "status": "confirmed",
      "note": "Подтверждён одинаковый вес на detalneftehim.ru и oporytrub.ru",
      "updated_at": "2026-03-11T12:00:00Z"
    }
  }
  ```

  Поля:

  - `name` — исходное обозначение опоры (ключ записи).
  - `sources` — список источников с доменом, URL, весом и временем получения.
  - `status` — агрегированный статус:
    - `confirmed` — несколько независимых источников дали одинаковый вес;
    - `single_source` — найден только один надёжный источник;
    - `conflict` — источники дают существенно разные значения;
    - `not_found` — ни один из доверенных источников не дал веса.
  - `note` — человекочитаемое примечание, объясняющее, что именно произошло.
  - `updated_at` — время последнего обновления записи.

### Публичное API модуля

Публичные функции планируются в модуле `ves.resolver`:

- `resolve_position(name: str) -> ResolvedPosition`  
  Принимает строку с обозначением опоры и возвращает структуру `ResolvedPosition`, которая содержит:

  - исходное поле `name`;
  - словарь `weights_by_domain: dict[str, float | None]` — найденные веса по доменам;
  - поле `status: Literal["confirmed", "single_source", "conflict", "not_found"]`;
  - поле `note: str` — короткое текстовое описание ситуации.

- `generate_pdf_zmk_ves_values(positions: list[str]) -> list[list[str]]`  
  Строит двумерный массив значений для листа Google Sheets `PDF_ZMK_VES`:

  - первая строка — заголовки: `["Позиция", "<domain1>", "<domain2>", ..., "Примечание"]`;
  - дальше по строке на каждую позицию.

Скрипт `write_pdf_zmk.py` будет вызывать именно `generate_pdf_zmk_ves_values` при обновлении листа `PDF_ZMK_VES`.

### Лист Google Sheets `PDF_ZMK_VES`

- Имя листа: `PDF_ZMK_VES`.
- Колонки:
  - `A` — исходная позиция (строка, как в `test_positions.txt` или другом входном списке);
  - `B, C, D, ...` — по одному столбцу на каждый используемый домен-источник (например, `detalneftehim.ru`, `oporytrub.ru`);
  - последняя колонка — `Примечание` с описанием статуса и возможных расхождений.

### Поток данных

1. Скрипт читает входной список позиций (на тестах — из `ves/test_positions.txt`).
2. Для каждой позиции вызывает `ves.resolver.resolve_position`.
3. Резолвер:
   - смотрит, есть ли актуальная запись в `ves/weights_db.json`;
   - при необходимости вызывает веб-скрейперы по доверенным сайтам;
   - обновляет кэш и возвращает агрегированную информацию.
4. Функция `generate_pdf_zmk_ves_values` формирует двумерный массив для `PDF_ZMK_VES`.
5. `write_pdf_zmk.py` очищает лист `PDF_ZMK_VES` и записывает туда сформированные значения.

# Полный контекст: лист «Вес» (ПМ) и каталоги К2К

Документ объединяет все правила, спецификации и наработки по заполнению веса для позиций опор, листу «Вес» в Google Таблице (pdf-eye) и каталогам К2К. Предназначен для использования в будущем (агент, разработка, онбординг).

---

## 1. Термины и обозначения

| Термин | Значение |
|--------|----------|
| **ПМ** | Лист «Вес» в Google Таблице pdf-eye (проект «Масса»). |
| **К2К** | Каталоги для второй колонки листа «Вес»: файлы `weight_sources_*.csv` в папке `data/`. Создаются и дополняются агентом. |
| **опм** | Команда «обнови ПМ»: переработать список опор по правилам и выгрузить результат на лист «Вес» (запуск `write_pdf_zmk.py`). |
| **1к** | Первая колонка весов — «Вес (1-й источник), кг». Источник обязан отличаться от источника 2к. |
| **2к** | Вторая колонка весов — «Вес (каталоги), кг». Заполняется только из К2К. |
| **ПВ** | Поверенный вес: вес совпал в обеих колонках два раза; в К2К позиция помечается « ПВ» в конце названия. Для ПВ 1к не заполняют. |
| **ППМ** | Правила проекта «Масса» — `docs/правила-проект-масса.md`. |
| **agent_weight_names.txt** | Файл в корне проекта: список опор и порядок строк на листе «Вес». Кодировка UTF-8. При добавлении — только дополнять (append), не перезаписывать целиком. |
| **Надёжный источник** | ОСТ/ГОСТ (текст или официальная таблица), официальный каталог производителя, нормаль с указанием массы. Только такие источники допускаются в К2К и на листе «Вес». |

---

## 2. Назначение двух колонок и К2К

- **Смысл двух колонок** — сверять вес из двух разных надёжных источников, чтобы не допустить ошибок.
- **2к** — только из К2К (`data/weight_sources_*.csv`). Подстановка по ключу (краткое обозначение), при нескольких совпадениях приоритет у каталога того же ОСТ/ГОСТ, что и в названии опоры.
- **1к** — вес из записи К2К с **другим исходным источником** (другой сайт/документ), чем запись, выбранная для 2к. Если для опоры в К2К только один исходный источник — в 1к ставится прочерк «-».
- **Различие источников** обеспечивается нормализацией поля «Источник»: для строк вида «… (site.ru)» берётся содержимое последних скобок (домен). Два файла с одного сайта считаются одним исходным источником.

---

## 3. Файлы и форматы

### 3.1 Каталоги К2К (`data/weight_sources_*.csv`)

- **Расположение:** `data/`, маска `weight_sources_*.csv` (например `weight_sources_ost36_146_88.csv`, `weight_sources_ost24_125_109.csv`).
- **Формат строки:** `Название опоры;Вес, кг;Источник`
  - Разделитель — точка с запятой (`;`).
  - Первая строка — заголовок: `Название опоры;Вес, кг;Источник`.
  - **Название опоры** — ключ для подстановки: краткое обозначение (например `57-ТР-А1`, `32-ХБ-Б`, `76-КП-А11`) или полное название опоры, если нужно точное совпадение с текстом из `agent_weight_names.txt`.
  - **Вес, кг** — число с запятой или точкой (например `1,4` или `0,18`). Пустой вес не подставляется.
  - **Источник** — реальный источник (сайт/документ). Для сайтов рекомендуется указывать домен в скобках в конце, например: `ДЕТАЛЬНЕФТЕХИМ ОСТ 36-146-88 ХБ`, `zavodopora ОСТ 36-146-88 КП А11/АС11`, `Теплоэнергопласт ОСТ 36-146-88 ТР`, `rus-line ОСТ 36-146-88 ТП`.

- **Объединение:** при формировании листа «Вес» все файлы `weight_sources_*.csv` читаются; при дубликате ключа побеждает последний файл по сортировке путей.
- **Правило:** каталоги можно только дополнять, нельзя удалять. Исправление ошибок в весе в существующих строках — только по команде пользователя.

### 3.2 Второй источник для 1к (`data/weight_sources_second_fallback.csv`)

- **Назначение:** для опор, у которых 2к заполнена, но в К2К только один исходный источник (1к = «-»), скрипт при выгрузке подмешивает строки из этого файла в соответствующий `weight_sources_<stem>.csv`, чтобы в первой же выгрузке заполнились и 1к, и 2к.
- **Формат:** тот же — `ключ;вес;источник` (разделитель `;`). Заголовок: `Название опоры;Вес, кг;Источник`.
- **Логика скрипта:** для каждой опоры из списка проверяется, есть ли в К2К хотя бы две записи с разными нормализованными источниками. Если нет — ищется ключ в fallback; если найден и источник в fallback отличается от источника записи для 2к — строка дописывается в файл `data/weight_sources_<stem>.csv`, где `stem` берётся из выбранной для 2к записи (например `weight_sources_ost36_146_88`).

### 3.3 Список опор (`agent_weight_names.txt`)

- Одна опора на строку. Порядок строк = порядок на листе «Вес».
- Названия могут быть длинными (с материалом, стандартом и т.д.); для подстановки веса достаточно, чтобы ключ из К2К входил в название (см. раздел 4).

## 4. Сопоставление названий со справочниками (логика подстановки)

Реализация в `write_pdf_zmk.py`: функции `_key_matches_name`, `_find_weight_by_substring`, `_find_two_weights_different_sources`.

### 4.1 Основное правило

- **Полное совпадение не требуется.** Ключ из К2К (например `57-КХ-А11`, `32-ХБ-Б`) должен **входить в название опоры** как подстрока или с учётом замены дефиса на пробел (`108К-04` ↔ `108К 04`). Выбирается вес по **самому длинному** подходящему ключу.

### 4.2 Эквивалентность А и АС (ОСТ 36-146-88)

Для типов **КП, КХ, ВП, ТХ, ТП** буква «С» в исполнении после «А» (сварной корпус) не меняет массу. При сопоставлении считаются эквивалентными:

- А11 и АС11 (например `76-КП-А11` матчится с «Опора 76-КП-АС11-…»)
- А21 и АС21, А22 и АС22
- А2 и АС2 (например `57-ВП-АС2`)
- А10 и АС10, А00 и АС00

Реализация: `_normalize_a_ac_for_matching` в `write_pdf_zmk.py` (замена АС11→А11 и т.д. только при наличии в строке одного из типов `-КП-`, `-КХ-`, `-ВП-`, `-ТХ-`, `-ТП-`).

### 4.3 Исключения

- **ОХК, БКХЛ, БКНХЛ:** если в названии опоры есть одно из этих сочетаний — вес не подставляется (обе колонки пустые). Константа `WEIGHT_EXCLUDE_SUBSTRINGS` в `write_pdf_zmk.py`.
- **Числовые ключи (диаметр/высота):** ключи, состоящие только из цифр и входящие в список диаметров (18, 25, 32, 45, 57, 76, 89, 108, 133, 159, 219, 273, 325, …) или высот (50, 100, 150, 200, …), **не используются** как единственный ключ — иначе один вес подставлялся бы разным типам опор. Для чисто числового ключа совпадение допускается только при контексте обозначения (после числа — дефис/пробел и буквы типа КХ, ХБ, КП).
- **Размер с дробью «, 100/200»:** если в названии есть шаблон `,\s*\d+/\d+`, короткие ключи из одних цифр длиной ≤ 4 символов не используются (чтобы не матчить по подстроке «100» или «200» из размера).

### 4.4 Сомнительная подстановка

Если вес подобран по ключу длиной **≤ 8 символов** и при этом нет точного совпадения имени опоры с ключом в справочнике, строка на листе «Вес» подсвечивается **жёлтым** (колонки B и C) как сомнительная.

### 4.5 Выбор записи для 2к при нескольких совпадениях

Записи сортируются: сначала из каталога **того же стандарта** (ОСТ/ГОСТ), что извлечён из названия опоры (например `ost36_146_88`, `24_125_109`), затем по убыванию длины ключа. Для 1к выбирается запись с **другим нормализованным источником**, чем у выбранной для 2к.

## 5. Обязательный порядок действий (чек-лист)

При **любой** работе с весами или листом «Вес» (выгрузка, опм, ответ на вопрос о весе, список опор) выполняются шаги **без напоминания и без отдельной команды пользователя**:

1. **По всем опорам из списка:** есть ли вес в К2К?
   - **Нет** → сначала **искать** точный вес в надёжных источниках (ОСТ/ГОСТ, каталог производителя, нормаль). Найден — добавить в К2К с указанием источника. Не найден после поиска — допускается пусто или пометка «вес не найден» в источнике; в К2К не вносить ориентировочные/придуманные значения.
   - Запрещено: добавлять в К2К пустой вес или «вес не найден» без предварительного поиска; подставлять ориентировочные или придуманные веса.

2. **По опорам, у которых 2к заполнена, но в К2К только один исходный источник (1к = «-»):**
   - Обязательно искать второй надёжный источник. Найден — добавить в К2К (в подходящий `weight_sources_*.csv` или в `data/weight_sources_second_fallback.csv`: `ключ;вес;источник`).
   - Делается до выгрузки, чтобы в первой же выгрузке были заполнены и 1к, и 2к.

3. В К2К и на листе «Вес» — **только точные веса из надёжных источников**. Запрещено: ориентировочные, расчётные, придуманные; дублировать один придуманный вес в 1к и 2к.

4. **Исправление ошибок в весе** в уже существующих строках К2К — только по команде пользователя.

5. **Для опор с ПВ** первую колонку не заполнять.

## 6. Структура листа «Вес» и подсветка

### 6.1 Колонки

| Колонка | Заголовок | Содержимое |
|---------|-----------|------------|
| A | Название опоры | Текст из списка (например из `agent_weight_names.txt`). |
| B | Вес (1-й источник), кг | Вес из записи К2К с другим источником, чем для 2к. Нет такой записи — «-». Для ПВ — пусто. |
| C | Вес (каталоги), кг | Вес только из К2К. |

Дополнительных колонок (например «Расхождение, %») нет — только подсветка цветом.

### 6.2 Выгрузка

- При каждой выгрузке **сначала очищается** весь лист «Вес», затем записываются заголовок и строки по текущему списку опор. Старые строки не сохраняются.

### 6.3 Подсветка (только колонки B и C)

- **Колонка A не выделяется** цветом никогда.
- **Сброс фона:** перед подсветкой сбрасывается фон в белый для колонки A (строки данных) и для колонок B и C.
- **Строки с ПВ:** колонки B и C — светло-зелёный.
- **Расхождение 1к и 2к:** колонки B и C — розовый. Пороги:
  - вес по К2К (колонка C) **≥ 1,5 кг** — подсветка при расхождении **> 5%**;
  - вес по К2К **< 1,5 кг** — только при расхождении **> 15%**.
- **Исключение:** опоры ХБ с диаметром до 45 включительно (18, 25, 32, 38, 45) при расхождении не выделяются.
- **Сомнительные:** вес по короткому ключу (≤ 8 символов) — колонки B и C жёлтым.

Реализация: `repeatCell` (Google Sheets API), диапазоны B:C — `startColumnIndex: 1, endColumnIndex: 3`; сброс A — `startColumnIndex: 0, endColumnIndex: 1`. Условное форматирование по формуле не используется; при выгрузке удаляются все существующие правила условного форматирования листа «Вес».

## 7. Скрипт и константы (`write_pdf_zmk.py`)

- **Пути:**
  - `WEIGHT_SOURCES_DIR = Path("data")`
  - `WEIGHT_SOURCES_GLOB = "weight_sources_*.csv"`
  - `WEIGHT_NAMES_TXT = Path("agent_weight_names.txt")`
  - `WEIGHT_SECOND_FALLBACK_CSV = WEIGHT_SOURCES_DIR / "weight_sources_second_fallback.csv"`
- **Лист:** `SHEET_NAME_WEIGHT = "Вес"`.
- **Прочерк при отсутствии данных 1к:** `WEIGHT_NO_DATA_MARK = "-"`.
- **Исключённые подстроки в названии:** `WEIGHT_EXCLUDE_SUBSTRINGS = ("ОХК", "БКХЛ", "БКНХЛ")`.
- **Пометка ПВ в К2К:** в конце названия опоры в CSV добавляется ` ПВ` (пробел + ПВ).

Перед формированием данных листа «Вес» вызывается `_ensure_second_sources_for_weight_sheet()` (подмешивание вторых источников из fallback в соответствующие `weight_sources_*.csv`), затем `get_support_weights_dual()` и запись в таблицу.

**Запуск опм:** выполнить `python write_pdf_zmk.py` (без аргументов — полная выгрузка, включая лист «Вес»). Для выгрузки только переданных опор: `python write_pdf_zmk.py --weight "Название опоры 1" "Название опоры 2"`.

## 8. Практика дополнения К2К (из обсуждений и сессий)

### 8.1 Если 2к пустая

Причина обычно одна: **в К2К нет записи с ключом, который матчится с названием опоры.** Примеры:

- В каталоге был `32-ХБ-А`, но не было `32-ХБ-Б` → добавлена строка `32-ХБ-Б;0,18;ДЕТАЛЬНЕФТЕХИМ ОСТ 36-146-88 ХБ`.
- По КП были размеры 57, 89, 108, 159, 219, 325…, но не было 76, 133, 273 для исполнения А11/АС11 → добавлены `76-КП-А11`, `133-КП-А11`, `273-КП-А11` с весами из каталога (zavodopora и т.п.).

**Действие:** найти точный вес в надёжных источниках (ОСТ/ГОСТ, каталог производителя), затем добавить строку в подходящий `weight_sources_*.csv` (например `weight_sources_ost36_146_88.csv`). Ключ — краткое обозначение (можно А11 вместо АС11 для КП/КХ/ВП/ТХ/ТП — матчинг по эквивалентности).

### 8.2 Если 2к заполнена, а 1к = «-»

В К2К только один исходный источник. Нужен второй источник с тем же весом (или подтверждённым тем же значением).

**Действие:** найти второй надёжный источник (другой сайт каталога, нормаль, ОСТ/ГОСТ) и добавить:
- либо вторую строку в тот же `weight_sources_*.csv` с другим «Источник» (другой домен/документ),
- либо строку в `data/weight_sources_second_fallback.csv` в формате `ключ;вес;источник`.

Примеры из сессий:
- ТР-А1 (57, 89, 108, 159): в каталоге был только Теплоэнергопласт → в second_fallback добавлены строки с источником rus-line ОСТ 36-146-88 ТР.
- 32-ТП-АС00: добавлены две строки в ost36_146_88 (Теплоэнергопласт и rus-line).
- ТО-А1 (89, 108, 219): добавлены в second_fallback с rus-line ОСТ 36-146-88 ТО.

### 8.3 Полное название в К2К

Если краткий ключ уже есть, но из-за разного написания (пробелы, дефисы) подстановка не срабатывает, в тот же каталог можно добавить **дополнительную строку с полным названием опоры** (как в списке) и тем же весом — сработает точное совпадение по имени.

### 8.4 Примеры добавленных записей (для справки)

- **32-ХБ-Б** — 0,18 кг (ДЕТАЛЬНЕФТЕХИМ ОСТ 36-146-88 ХБ).
- **32-ТП-АС00** — 0,6 кг (Теплоэнергопласт + rus-line).
- **ВП-АС2:** 57, 76, 89 — 1,2 кг; 108, 159 — 4,4 кг (zavodopora ОСТ 36-146-88 ВП АС1/АС2).
- **76-КП-А11, 133-КП-А11, 273-КП-А11** — 1,3; 1,5; 2,6 кг (zavodopora ОСТ 36-146-88 КП А11/АС11).
- **ТР-А1** (57, 89, 108, 159) — второй источник в second_fallback: rus-line ОСТ 36-146-88 ТР с весами 1,4; 1,9; 1,9; 3,2 кг.

## 10. Краткая памятка для агента

1. Список опор → обработать по ППМ и выгрузить на лист «Вес» (при необходимости — опм).
2. По каждой опоре: есть вес в К2К? Нет → искать в надёжных источниках → добавить в К2К.
3. По каждой опоре с заполненной 2к и одним источником в К2К: искать второй источник → добавить в К2К или в `weight_sources_second_fallback.csv`.
4. В К2К и на листе — только точные веса из надёжных источников; исправлять существующие веса в К2К только по команде пользователя.
5. Для ПВ первую колонку не заполнять.

При противоречии между этим документом и актуальной версией ППМ или правил в `.cursor/rules/` ориентироваться на `docs/правила-проект-масса.md` и указанные правила.
